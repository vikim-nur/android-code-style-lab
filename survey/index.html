Как будем оформлять Kotlin в команде

Посмотрите код и выберите удобный вариант в каждом вопросе. Здесь 10 вопросов по конкретным настройкам. Статический анализ Detekt будем обсуждать отдельно.

За основу взят кандидат по эталону. Пометка «В предложении по эталону» показывает, что сейчас настроено в нём; ответ за вас не выбран. Можно предложить конкретное изменение в комментарии.

Все примеры учебные. Жёлтым выделены строки, отличающиеся между вариантами.


1. Длина строки

Где разрешаем более длинную строку: до 120 или до 140 символов? На первом выражении видно, когда появляется перенос после знака =.

fun message() {    val displayMessage =        cachedMessage ?: repository.loadMessageForAccount(currentAccountIdentifier, selectedLanguageCode)    val selectedItem = repository.loadAvailableItemsForCurrentSession(        currentAccountIdentifier,        selectedCategoryIdentifier,        includeArchivedItems    ).firstOrNull()}

В предложении по эталону

2. Последняя запятая в вызове

Нужна ли запятая после последнего аргумента перед закрывающей скобкой? Речь о вызовах, которые уже записаны на нескольких строках.

fun card() {    renderCard(        title = title,        count = count,        onClick = onClick,    )}

В предложении по эталону

fun card() {    renderCard(        title = title,        count = count,        onClick = onClick    )}

Выбор запятой сейчас не требует отключать наше правило компактной вложенной лямбды. Обновлённые примеры проверены с JAR 0.2.0-candidate.1.

3. Последняя запятая в объявлении

Тот же выбор для параметров функции или конструктора класса. Это отдельная настройка от запятой при вызове.

data class CardOptions(    val title: String,    val count: Int,    val enabled: Boolean,    val subtitle: String,)

В предложении по эталону

data class CardOptions(    val title: String,    val count: Int,    val enabled: Boolean,    val subtitle: String)

Выбор запятой сейчас не требует отключать наше правило компактной вложенной лямбды. Обновлённые примеры проверены с JAR 0.2.0-candidate.1.

4. Параметры функции

Нужно ли с четырёх параметров всегда переносить их столбиком? Вариант «можно в строку» всё равно переносит слишком длинные объявления.

fun renderCard(title: String, count: Int, enabled: Boolean, onClick: () -> Unit) {    show(title)}

В предложении по эталону

fun renderCard(    title: String,    count: Int,    enabled: Boolean,    onClick: () -> Unit) {    show(title)}
Тот же выбор на обработчике адаптера

Этот пример использует тот же ответ выше; ещё раз голосовать не нужно. Даже без принудительного порога длинная строка может перенестись по общему лимиту.

Можно в строку, если помещается

fun installListener() {    view.onItemSelectedListener = object : AdapterView.OnItemSelectedListener {        override fun onItemSelected(parent: AdapterView<*>?, view: View?, position: Int, id: Long) {            selectItem(position)        }        override fun onNothingSelected(parent: AdapterView<*>?) = Unit    }}

От четырёх — столбиком

fun installListener() {    view.onItemSelectedListener = object : AdapterView.OnItemSelectedListener {        override fun onItemSelected(            parent: AdapterView<*>?,            view: View?,            position: Int,            id: Long        ) {            selectItem(position)        }        override fun onNothingSelected(parent: AdapterView<*>?) = Unit    }}

6. Аргументы при вызове

С четырьмя параметрами функция может объявляться столбиком, а её короткий вызов оставаться в строку. Нужно ли переносить и вызов?

В предложении по эталону

fun card() {    renderCard(title, count, enabled, onClick)}
fun card() {    renderCard(        title,        count,        enabled,        onClick    )}

7. Пустые строки в when

Нужна ли пустая строка после большой ветки? В предложении по эталону между короткими ветками лишних пустых строк нет.

В предложении по эталону

8. Короткий intent

Должен ли форматтер сам собирать короткий intent в строку? Короткий здесь: одно выражение без комментариев; вся строка с отступом — не длиннее 120 символов.

private fun back() = intent {    postSideEffect(Effect.Back)}

В предложении по эталону

private fun back() = intent { postSideEffect(Effect.Back) }

9. Цепочки Modifier

Начиная со скольких вызовов переносим каждый шаг Modifier на отдельную строку? Обычную короткую цепочку text.trim().lowercase() это правило не переносит.

В предложении по эталону

10. Наследование, адаптер и ViewHolder

Посмотрите оформление базового класса, generic-типов и вложенного ViewHolder. Принимаем показанный вид или предлагаем конкретный другой образец? Требовать определённый базовый класс — отдельный вопрос архитектуры.

В предложении по эталону

class SummaryViewModel @Inject constructor(private val repository: Repository) : BaseViewModel<SummaryState>(SummaryState()) {} class RowAdapter(private val onClick: (Row) -> Unit) :    ListAdapter<Row, RowAdapter.Holder>(        RowDiff()    ) {    inner class Holder(private val binding: RowBinding) : RecyclerView.ViewHolder(binding.root)}

Другой перенос базового класса может потребовать изменения алгоритма. По одному пожеланию в анкете не обещаем готовый переключатель: сначала проверим желаемый пример.

Передать ответы

Нажмите «Скачать ответы для чата» и передайте текстовый файл организатору обсуждения. Ответы не отправляются автоматически и не сохраняются на сервере.

Сохранить анкету, чтобы продолжить позже

После закрытия страницы несохранённые ответы исчезнут. Скачайте JSON и загрузите его сюда при следующем посещении. Прежняя редакция не импортируется автоматически: примеры и смысл отдельных настроек обновлены.

Передать ответ через GitHub

Нужен GitHub-аккаунт. Кнопка откроет черновик; отправлять его нужно самостоятельно. После отправки ответ будет публичным.

После ответов соберём выбранную комбинацию правил и проверим её целиком. Голосование само по себе не включает правила в проектах.

На чём основаны примеры

JAR 0.2.0-candidate.1, ktlint 1.8.0. Каждый вариант получен форматтером на базе кандидата по эталону с указанным изменением; повтор и проверка прошли. Комбинация будущих ответов команды ещё не тестировалась. Результаты проверки примеров.
