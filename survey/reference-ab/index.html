Как будем оформлять Kotlin?

А — оформление из выбранного образца «Мой О!». Б — альтернативный вариант. Посмотри на код и выбери, как тебе удобнее читать. Правильного ответа здесь нет.

Имена и логика в примерах упрощены. В самом «Мой О!» встречаются разные формы: А показывает конкретный найденный образец, а не единое правило всего проекта. Одинаковые варианты не спрашиваем.

Это анкета для согласования. Ответы с именами и GitHub-аккаунтами в публичных Issues видны всем. Победившие варианты ещё нужно согласовать с лидами и проверить вместе.

В результатах будут имя и аккаунт GitHub. Можно ответить на часть вопросов и позже изменить свою анкету.

Общие условия для всех примеров

Предел строки — 140 символов. Отдельного варианта с 200 нет: такое значение использовалось для воспроизведения длинной исходной строки и не было подтверждённой настройкой «Мой О!».

Если условие длиннее предела, оно переносится. Вот результат при 140:

fun update() {
    if (!isLoading && state.availableCustomerContractServiceItems.isEmpty() &&
        state.availableInternationalSubscriptionServiceItems.isEmpty()
    ) {
        showEmptyState(isActive = false)
    }
}

В вопросе о data class сравниваем два параметра. При трёх и более в обоих вариантах параметры располагаются столбиком:

data class LinkInfo(
    val name: String?,
    val link: String?,
    val description: String?
)

Обычные классы этот порог не затрагивает. Для одного-двух параметров сохраняются ограничения длины строки и сложных конструкций.

Есть замечание или другой пример?

Кнопка GitHub откроет черновик Issue. Проверь его и нажми Create / Submit new issue на GitHub. После отправки в Issue будет ссылка «Посмотреть результаты»: она откроет сводку и загрузит голоса. Сама анкета ничего не отправляет и не просит токен.
