Какие бывают правила?

Общие настройки: отступы, предел 140 символов, порядок импортов, последние запятые. Они задают общий стиль поддерживаемых конструкций.

Правила конструкций Kotlin: отдельно для data class, конструкторов с Inject, функций с телом после =, наследования или веток when. Парсер распознаёт устройство кода; область действия задаётся явно.

Шаблоны проекта: например, цепочки Modifier и короткий intent с одним выражением. Сейчас они распознаются по синтаксису/написанию, без разрешения типов библиотек.

Пустая строка в одном BaseNurTheme не означает, что она нужна каждой функции. Если правило должно работать только в части блоков, нужно описать условие и проверить похожие случаи. В каждом вопросе ниже указано, что затрагивает текущая реализация.

Есть замечание или другой пример?

Кнопка GitHub откроет черновик Issue. Проверь его и нажми Create / Submit new issue на GitHub. После отправки в Issue будет ссылка «Посмотреть результаты»: она откроет сводку и загрузит голоса. Сама анкета ничего не отправляет и не просит токен.
