# Android Code Style Lab

Согласовываем форматирование Kotlin на настоящих фрагментах «Мой О!». **А — оригинальный код, Б — альтернативное оформление того же кода.** Имена и логика сохранены. Detekt рассматривается отдельно; правила ещё не приняты и не внедрены в приложения.

## Что сравниваем

23 сравнения в 21 карточке: общие настройки, конструкции Kotlin и шаблоны проекта (Modifier, intent). У каждого примера указаны исходный файл и строки снимка от 18 ноября 2026 года. Где показан только заголовок, это отмечено; важный контекст раскрывается рядом. Найденная форма — пример, а не доказательство единой конвенции проекта.

Вместо учебного closeScreen показан настоящий BaseNurTheme. Пустая строка в одной сложной функции не означает, что её нужно добавлять во все короткие функции. Область действия обсуждаем отдельно.

Общий предел строки — 140. Для data class альтернатива: с трёх параметров столбиком, один-два в строку при подходящей длине. У обычных классов отдельный порог.

## Как проголосовать

1. Укажите имя, выберите А/Б и при желании оставьте комментарий со своим вариантом. Можно ответить на часть вопросов.
2. Нажмите «Открыть ответ в GitHub» и отправьте подготовленный Issue из своего аккаунта кнопкой Submit new issue. Открытый черновик ещё не сохраняет голос. Токен и приглашение в репозиторий не нужны.
3. В Issue нажмите «Посмотреть результаты голосования»: сводка откроется и загрузит ответы.

Репозиторий публичный: код примеров, имена и ответы доступны всем. Считается последняя анкета каждого аккаунта. Пропуски не голосуют; ничья показана отдельно. Закрытие Issue не отменяет голос. При удалении последнего ответа может снова учитываться предыдущий. Организатор сверяет участников с командой.

**У новой анкеты своя версия.** Старые ответы на учебные примеры остаются в Issues, но в новый подсчёт не включаются. Содержание нельзя менять под той же версией после начала голосования.

## Что проверено

На копиях 23 полных файлов обе стороны проходят format → repeat → check. Все 23 показанных исходных фрагмента восстанавливаются из Б; хеши и точные позиции сверены. 46 сравнений CLI с загрузчиком и движком IDE совпали. Это не ручная проверка шортката и не Android-сборка.

Использован экспериментальный JAR 0.4.0-ballot.1 с ktlint 1.8.0. JAR и полные исходные файлы в эту публикацию не входят. Конфиги приведены для отдельных опытов. Все комбинации решений не проверялись; после голосования нужно проверить итоговый профиль и согласовать его с лидами. Некоторые настройки влияют на соседние конструкции — подробности в карточках и пояснениях.

Проверка логики голосования: `node --test scripts/test_ballot.cjs`. Автоматические проверки используют подставленные ответы и не создают настоящие голоса.
