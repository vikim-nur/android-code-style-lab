# Предлагаемый стиль Kotlin

Статус: предложение для обсуждения, не командный стандарт.

- ktlint 1.8.0, android_studio как исходный профиль; четыре пробела.
- Предлагаемый лимит 140 символов; длинные литералы и комментарии не всегда исправляются автоматически.
- Объявления функций и конструкторов с 4+ параметрами — многострочные.
- Число аргументов вызова само по себе не требует переноса.
- В уже многострочных вызовах каждый аргумент — отдельно, включая большие вызовы.
- Распознанные Modifier-цепочки с двух вызовов — по вызову на строку.
- Короткие обычные цепочки могут оставаться в строку.
- Завершающие запятые сохраняются в обоих допустимых видах.
- Пустые строки when пока оставлены автору.
- Короткий intent без комментариев с одним выражением может собираться в строку до 120 символов.
- Пробелы у типов и наследования нормализует штатный colon-spacing.
- Группы java/javax/kotlin — в конце импортов, alias после них.

Точный профиль — ../config/formatting.proposed.editorconfig. Ему необходим JAR наших правил. Параметры анкеты сравниваются по одному поверх экспериментального исходного профиля. После выбора команды комбинацию нужно проверить целиком. Учебные Kotlin-фрагменты проверены форматтером, не компиляцией Android-приложения.

Штатный wrapping выключен ради нашей замены вложенных лямбд. Строгие правила trailing comma требуют именно штатный wrapping: в соответствующих вариантах анкеты замена выключена. Это ограничение текущей реализации, а не невозможность дальнейшей доработки.

Предлагаемый профиль пока отдельный: в ресурсах транспортного прототипа лежит прежний тестовый профиль. Не подменять его незаметно до согласования и повторной проверки Studio.


## Что берём за основу оформления

Ниже полный перечень рассматриваемых областей оформления. Это наблюдения и проект соглашений, а не 23 автоматически принятых запрета.

| Область | Предлагаемое поведение |
|---|---|
| Отступ | Четыре пробела |
| Modifier-цепочки | Наше узкое правило, порог 2 |
| Обычные цепочки | Не переносить по одному лишь порогу Modifier |
| Многострочные вызовы | Аргументы отдельно |
| Большие вызовы | Без исключения для 9+ аргументов |
| Короткие вызовы | Разрешена одна строка |
| Длинные объявления функций | Порог 4 параметра для принудительного переноса |
| Короткие объявления | Допустим ручной многострочный вид |
| Конструкторы | Отдельный порог 4 |
| Запятая в вызове | Сохраняем оба вида до решения команды |
| Запятая в объявлении | Отдельное решение, пока сохраняем оба вида |
| Expression body | Разрешено начало рядом с = |
| Короткая лямбда | Компактная форма допустима; intent — дополнительный узкий кандидат |
| Скобки when | Не требуем унификации всех коротких веток |
| Пустые строки when | Пока ручной выбор |
| Аннотации DTO | Сохраняет штатный formatter, отдельного исключения без подтверждённого конфликта не вводим |
| Порядок импортов | java/javax/kotlin в конце, alias после |
| Ширина строки | 140 как обсуждаемый кандидат |
| if с переносами | Не обещаем произвольную настройку по смыслу условий |
| Пустая строка в начале функции | Допускаем существующий ручной вариант |
| Конец файла | Один завершающий перевод строки |
| Наследование | Стандартный пробел перед двоеточием |
| Внешние скобки вокруг вложенной лямбды | Сохраняем компактный наблюдаемый шаблон своей заменой wrapping |

Сохранить ручной вариант, разрешить два вида и автоматически привести любой ввод к единственному виду — разные требования. Отключение широкой проверки реализует только часть этих требований.

## Как сравнивать примеры анкеты

Вопросы F01–F09 показывают одни и те же учебные входы при разных настройках. Даже если результаты двух вариантов совпадут, код показан полностью. Ни один ответ не выбран заранее.

Каждый вариант испытывался отдельно поверх исходного экспериментального профиля. Целый пример в начале анкеты получен совместным предлагаемым профилем. Изменение ответов не меняет ни этот пример, ни файл конфига автоматически. После выбора команда получает отдельный собранный профиль и новый совместный прогон.
