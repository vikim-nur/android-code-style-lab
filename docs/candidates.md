# Два воспроизводимых кандидата форматирования

Версия 0.2.0-candidate.1. Статус: кандидаты; командой не утверждены. [Открыть сравнение](https://vikim-nur.github.io/android-code-style-lab/comparison/).

## Что собрали

- A: профиль по разобранным шаблонам, с явными решениями для мест, где исходники различаются.
- B: штатный ktlint_official с явно выбранным лимитом 120. Это вариант поддерживаемого движка, не универсальный «best practice» и не точная копия Google Style.
- Один versioned JAR для engine ktlint 1.8.0. В A включены шесть из восьми наших правил; в B весь ruleset nur отключён.
- Из прежних пяти правил сохранены алгоритмы. Добавлены две адаптации штатной логики запятых и одно правило промежутков when. Повторно писать логику запятых не стали: делегируем ktlint той же версии и задаём зависимость от нашей замены wrapping.

## Явные решения A

Четыре пробела; ширина 140; функция/конструктор от четырёх параметров — столбиком; короткие вызовы не переносятся по одному лишь числу аргументов; в многострочном вызове аргументы отдельно без исключения больших списков; распознанный Modifier от двух вызовов — столбиком; обычные короткие цепочки допустимы; без последних запятых в вызовах и объявлениях; после многострочной ветки when одна пустая строка, после короткой — без пустой строки; стандартные пробелы у типов/наследования; нормализован конец файла и удалена пустая первая строка функции. Компактная вложенная лямбда разрешена; короткий intent до 120 — дополнительное пожелание, не доказанная обязательная норма исходного эталона.

140, порог 4, отсутствие всех trailing commas, пробел наследования и нормализация EOF/начала функции — явные решения кандидата, а не утверждение, что именно так было абсолютно во всём эталоне. Предыдущие снимки и конфиги сохраняются для истории.

## Где границы

Этот набор не является математически единственным форматированием любого допустимого Kotlin-ввода. Некоторые штатные правила сохраняют разрешённую вручную многострочную запись; мы не называем отключение проверки автоматическим приведением к одному образцу. Компактный intent не разворачивает уже однострочный блок обратно. Многострочный if без скобок и произвольная смысловая расстановка переносов не превращаются в универсальное семантическое автоисправление. Требование конкретного BaseViewModel или BaseModel вообще не задаётся formatter.

Modifier определяется консервативно по синтаксису/импортам/параметрам без полного type resolution. Правило when не перемещает комментарии между ветками и пропускает неоднозначные разделители. Новые comma-адаптеры запускаются только после включённого nur:nested-lambda-wrapping. Правила проверены на двух режимах commas false/true, каждый на 22 файлах.

Проверка нового JAR через loader/engine IDE-плагина подтверждена, но полный UI Sync/шорткат с этой версией в Studio, реальные hooks/CI и Android-пилот ещё не выполнены. Не переносим сюда старую UI-проверку JAR 0.1 как доказательство новой версии.

## Восстановление и запуск

JDK21 для сборки, bytecode Java17; Gradle9.4.1, ktlint1.8.0.

```sh
./gradlew :ktlint-rules:jar
./gradlew -p tooling/nur-quality-plugin build
```

Собранный JAR: tooling/nur-ktlint-rules/build/libs/ktlint-rules-0.2.0-candidate.1.jar. Готовая копия для проверки лежит в artifacts/nur-style-rules-0.2.0-candidate.1.jar, контрольные суммы в artifacts/manifest.json.

Для изолированной проверки своих учебных файлов: поместите выбранный config/profiles/*.editorconfig как .editorconfig в отдельную копию, затем из неё вызовите engine с --ruleset=/полный/путь/к/JAR и --format Example.kt. Для проверки без исправления уберите --format. В B тот же прикреплённый JAR не влияет на результат: ktlint_nur=disabled.

```sh
python3 scripts/verify_profiles.py --cli /path/to/ktlint-1.8.0-all.jar --rules artifacts/nur-style-rules-0.2.0-candidate.1.jar --output /path/to/owned-result
```

Скрипт изменяет только копии учебных файлов в output; не передавайте рабочий checkout приложения как каталог результатов. Транспортный прототип упаковывает A непосредственно из config/profiles/nur-reference.editorconfig: второго editable runtime-конфига теперь нет. Версия plugin/rules задаётся release в tooling/nur-quality-plugin/src/main/resources/quality/versions.properties.

## На что опирается второй вариант

[Документация ktlint1.8.0](https://ktlint.github.io/ktlint/1.8.0/rules/configuration-ktlint/) описывает поддерживаемые профили, включая ktlint_official. [Kotlin coding conventions](https://kotlinlang.org/docs/coding-conventions.html) — источник общих соглашений. [Google Android Kotlin Style](https://developer.android.com/kotlin/style-guide) — отдельный документ, его не отождествляем с именем профиля android_studio или ktlint_official.
