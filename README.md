## Что сравниваем

23 сравнения в 21 карточке: общие настройки, конструкции Kotlin и шаблоны проекта (Modifier, intent). Примеры взяты из снимка от 18 ноября 2026 года. Где показан только заголовок, это отмечено. Источники сохранены в данных анкеты; в карточках показано только сравнение оформления. Найденная форма — пример, а не доказательство единой конвенции проекта.

Вместо учебного closeScreen показан настоящий BaseNurTheme. Пустая строка в одной сложной функции не означает, что её нужно добавлять во все короткие функции. Область действия обсуждаем отдельно.

Общий предел строки — 160. Для data class альтернатива: с трёх параметров столбиком, один-два в строку при подходящей длине. У обычных классов отдельный порог.

Аннотации свойств выбираем только для `val`/`var` в основном конструкторе `data class`: JSON, Room и другие аннотации. Наличие `@Parcelize` не меняет область правила. Параметры обычных функций и конструкторы обычных классов, включая DI, этим переключателем не затрагиваются. Аннотации самого класса остаются отдельным случаем.

## Как проголосовать

1. Укажите имя, выберите А или Б во всех вопросах и при желании оставьте комментарий со своим вариантом.
2. Нажмите «Продолжить в GitHub», затем в заполненной форме нажмите Submit new issue, чтобы отправить ответы и комментарий. Открытый черновик ещё не сохраняет голос. Токен и приглашение в репозиторий не нужны.
3. В Issue нажмите «Посмотреть результаты голосования»: сводка откроется и загрузит ответы.

Репозиторий публичный: код примеров, имена и ответы доступны всем. Считается последняя анкета каждого аккаунта. Пропуски не голосуют; ничья показана отдельно. Закрытие Issue не отменяет голос. При удалении последнего ответа может снова учитываться предыдущий. Организатор сверяет участников с командой.

**У новой анкеты своя версия.** Ответы на предыдущие версии, включая вариант с лимитом 140, остаются в Issues, но в новый подсчёт не включаются. Содержание нельзя менять под той же версией после начала голосования.

## Что проверено

На копиях 23 полных файлов обе стороны проходят format → repeat → check. Все 23 показанных исходных фрагмента восстанавливаются из Б; хеши и точные позиции сверены. 46 сравнений CLI с загрузчиком и движком IDE совпали. Это не ручная проверка шортката и не Android-сборка.

Использован экспериментальный JAR 0.4.0-ballot.2 с ktlint 1.8.0. JAR и полные исходные файлы в эту публикацию не входят. Конфиги приведены для отдельных опытов. Все комбинации решений не проверялись; после голосования нужно проверить итоговый профиль и согласовать его с лидами. Некоторые настройки влияют на соседние конструкции — подробности в карточках и пояснениях.

Проверка логики голосования: `node --test scripts/test_ballot.cjs`. Автоматические проверки используют подставленные ответы и не создают настоящие голоса.
