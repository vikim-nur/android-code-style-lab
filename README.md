# Android Code Style Lab

Приватная лаборатория общего оформления Kotlin. Сейчас выбираем форматирование; статический анализ обсуждается отдельно. Правила не утверждены и не подключены к приложениям.

## Начать здесь

Откройте `survey/index.html` в браузере: девять вопросов, учебные примеры, сохранение ответов в JSON без отправки на сервер. [Предлагаемые соглашения](docs/formatting.md), [пять custom rules](docs/custom-rules.md), [решения](docs/decisions.md).

| Каталог | Содержимое |
|---|---|
| config | Предлагаемый профиль форматирования |
| survey | Анкета на самостоятельных учебных примерах |
| examples | Целый учебный файл до и после |
| tooling/nur-ktlint-rules | Исходники пяти formatter rules |
| tooling/nur-quality-plugin | Прежний прототип доставки конфигов/JAR через Gradle Sync |

Реальные фрагменты приложений и рабочие заметки остаются вне этого репозитория. В Git включены только общие инструменты, документация и учебные примеры. Публичный хостинг анкеты не включён.

## Сборка правил

JDK 21 для сборки, bytecode Java 17. Gradle и Kotlin закреплены; CLI ktlint 1.8.0.

```sh
./gradlew :ktlint-rules:jar
```

Транспортный прототип собирается отдельно:

```sh
./gradlew -p tooling/nur-quality-plugin build
```

Это исходники эксперимента, не установленный IDE-плагин. IDE-плагин ktlint ставится отдельно. Не копируйте предлагаемый профиль в приложения без согласования: часть правил custom и требует нашего JAR.

## Статус проверки

Учебные варианты проверяются настоящим ktlint: format/repeat/check. Результаты — `docs/example-verification.json`. Это не компиляция приложения, запуск UI, хука или CI. Настоящие замеры Android и проверка итогового согласованного профиля впереди.

Предлагаемый профиль в config отличается от прежнего тестового профиля в транспортном прототипе. Детект-конфиг прототипа — технический smoke control, не командная политика. Не использовать его как готовые принятые правила.

Версия `0.1.0-prototype` экспериментальная. Теги релизов пока не создаются. [Перенос в корпоративный Git](docs/migration.md) сохраняет историю; приложения подключаются отдельным этапом после утверждения.
